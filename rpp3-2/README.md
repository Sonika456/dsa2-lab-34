# Лабораторная работа №3. Раздел III
## Тема: Реализация жизненного цикла бизнес-сущности

### Предметная область
**Аренда электросамоката**

### Цель
Реализовать жизненный цикл ключевой сущности (поездка) с помощью паттерна «Состояние» (GoF) и оркестрировать бизнес-процесс согласно BPMN-схеме.

### Архитектура
Проект реализован в соответствии с тактическим Domain-Driven Design (DDD):

- **Доменный слой** (`domain/`): агрегаты, объекты-значения, порты, доменные события
- **Прикладной слой** (`application/`): оркестрация бизнес-процесса
- **Инфраструктурный слой** (`infrastructure/`): In-Memory адаптеры

### Ключевые особенности реализации

1. **Паттерн «Состояние» (GoF)**
   - 9 состояний агрегата `Trip` согласно Таблице 4а методического руководства
   - Базовый класс `TripState` объявляет все 9 событий, по умолчанию запрещает их
   - Конкретные состояния переопределяют только допустимые переходы
   - Состояние хранится в закрытом атрибуте `_state`, публичного сеттера нет

2. **Оркестрация BPMN-схемы**
   - Прикладной сервис `RentalProcess` связывает схему процесса с доменной моделью
   - Каждой задаче схемы соответствует метод сервиса
   - Условия шлюзов реализованы через предикаты
   - Параллельные ветви выполняются последовательно, агрегат хранит флаги завершения

3. **Управление временем**
   - Протокол `Clock` абстрагирует время
   - `ShiftedClock` позволяет тестировать таймеры без реального ожидания
   - Защита от перевода часов назад

4. **Доменные события**
   - 14 событий фиксируют значимые факты предметной области
   - Все события неизменяемы (`frozen=True`)
   - Журнал событий хранится в агрегате
